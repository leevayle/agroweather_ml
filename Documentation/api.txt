5. API STARTUP AND PERFORMANCE
==============================

When FastAPI starts, api.py imports forecast_engine.py.
The trained ML models are loaded into memory once.

The intended flow is:

    API starts
        |
        +--> load ML models into RAM
        |
        +--> start server
        |
        +--> serve requests

Models should not be loaded from disk for every request.

The normal forecast is also cached, so repeated requests do not
unnecessarily recalculate the same forecast.

7. GET /
=========

Purpose:
    Returns the latest current-weather data held by the backend.

Request:

    GET /

Example:

    http://127.0.0.1:8000/

Example response:

    {
      "status": "success",
      "type": "current_weather",
      "data": {
        "temperature_c": 21.7,
        "humidity_percent": 78.4,
        "day_night": "day",
        "rainfall_mm": 2.3,
        "rain_status": "raining",
        "wind_speed_kmh": 9.8,
        "wind_direction": "NE",
        "pressure_hpa": 1014.8,
        "timestamp": "2026-09-24T18:35:12",
        "source": "ESP32"
      }
    }

Important fields:

    temperature_c
        Current temperature in Celsius.

    humidity_percent
        Current relative humidity percentage.

    day_night
        Day/night state.

    rainfall_mm
        Current/recent rainfall measurement.

    rain_status
        Human-readable rain state.

    wind_speed_kmh
        Current wind speed.

    wind_direction
        Current wind direction.

    pressure_hpa
        Atmospheric pressure in hPa.

    timestamp
        Time the backend last received the reading.

    source
        Current data source, normally ESP32.

If no sensor data is available, values may be null:

    "temperature_c": null

The frontend should show something such as:

    Waiting for station data...

or:

    --

9. GET /forecast
================

Purpose:
    Returns the standard ML weather forecast.

Default:
    5 days

Request:

    GET /forecast

Example:

    http://127.0.0.1:8000/forecast

Response structure:

    {
      "status": "success",
      "forecast_days": 5,
      "forecast": [
        {
          "date": "2025-10-25",
          "temperature": {
            "avg_c": 19.58,
            "min_c": 15.92,
            "max_c": 25.24
          },
          "rainfall": {
            "rain": true,
            "probability": 0.80,
            "amount_mm": 4.2
          },
          "wind_speed": 9.5,
          "pressure_hpa": 1014.7
        }
      ]
    }


10. GET /forecast?days=N
========================

Purpose:
    Requests a specific number of forecast days.

Example:

    http://127.0.0.1:8000/forecast?days=7

Supported range:

    Minimum: 1 day
    Maximum: 30 days

Examples:

    /forecast?days=5
    /forecast?days=7
    /forecast?days=14
    /forecast?days=30

Invalid:

    /forecast?days=0

Expected:
    HTTP 400 Bad Request

Invalid:

    /forecast?days=31

Expected:
    HTTP 400 Bad Request


11. FORECAST RESPONSE FIELDS
============================

Each forecast day contains:

    date
        Forecast date in YYYY-MM-DD format.

    temperature.avg_c
        Predicted average temperature in Celsius.

    temperature.min_c
        Predicted minimum temperature in Celsius.

    temperature.max_c
        Predicted maximum temperature in Celsius.

    rainfall.rain
        Boolean indicating whether rain is predicted.

    rainfall.probability
        Model probability from the rain/no-rain classifier.
        Example: 0.82 means an 82% model probability, not a
        guarantee.

    rainfall.amount_mm
        Predicted rainfall amount in millimetres.

    wind_speed
        Predicted wind speed.

    pressure_hpa
        Predicted pressure in hPa.


12. GET /forecast/range
=======================

Purpose:
    Requests a forecast for a specific date range.

Format:

    GET /forecast/range?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD

Example:

    http://127.0.0.1:8000/forecast/range?start_date=2025-11-01&end_date=2025-11-07

This requests 7 days.

Response:

    {
      "status": "success",
      "start_date": "2025-11-01",
      "end_date": "2025-11-07",
      "forecast_days": 7,
      "forecast": [
        ...
      ]
    }

Date format must be:

    YYYY-MM-DD

Correct:

    2025-11-01

Incorrect:

    01/11/2025


13. FORECAST RANGE LIMIT
========================

Maximum range:

    30 days

Example of a valid 30-day request:

    /forecast/range?start_date=2025-11-01&end_date=2025-11-30

A range longer than 30 days returns:

    HTTP 400 Bad Request


14. FORECAST BEHAVIOUR
======================

The current ML system is recursive.

Conceptually:

    Day 1 prediction
        |
        v
    helps predict Day 2
        |
        v
    helps predict Day 3
        |
        v
       ...

Because predictions are reused for later predictions, uncertainty
can accumulate over longer forecast horizons.

Forecasts are model predictions, not guarantees.

20. HTTP STATUS CODES
=====================

200 OK
    Request succeeded.

400 Bad Request
    Invalid request parameters.

Examples:
    days < 1
    days > 30
    invalid date range
    range > 30 days

500 Internal Server Error
    An unexpected backend error occurred.

For 500 errors, check the Uvicorn terminal for the traceback.


21. PERFORMANCE DESIGN
======================

ML models:

    Loaded once at API startup
        |
        v
    kept in RAM
        |
        v
    reused by requests


Current weather:

    latest reading
        |
        v
    in-memory current_weather
        |
        v
    GET /


Normal forecast:

    first request
        |
        v
    forecast calculation
        |
        v
    cached in RAM

Later requests:

    GET /forecast
        |
        v
    cached result


This prevents repeated disk model loading and unnecessary
forecast calculations.

23. TROUBLESHOOTING
===================

Problem:
    'uvicorn' is not recognized.

Fix:

    C:\agroweather\.venv\Scripts\Activate.ps1

Then:

    uvicorn api:app --host 0.0.0.0 --port 8000 --reload


Problem:
    No module named fastapi

Fix:

    pip install fastapi uvicorn requests


Problem:
    No module named joblib

Fix:

    pip install joblib


Problem:
    Forecast fails because a model is missing.

Check:

    C:\agroweather\ml\models

Make sure these exist:

    temperature_avg_model.pkl
    temperature_min_model.pkl
    temperature_max_model.pkl
    rain_classifier.pkl
    rainfall_amount_model.pkl
    wind_speed_model.pkl
    pressure_model.pkl


Problem:
    API starts but forecast fails.

Check:

    http://127.0.0.1:8000/health

Then:

    http://127.0.0.1:8000/docs

Also inspect the Uvicorn terminal for the traceback.


Problem:
    Another device cannot access the API.

Check:

    1. Start with:
       uvicorn api:app --host 0.0.0.0 --port 8000 --reload

    2. Both devices are on the same network.

    3. Use the PC's LAN IP instead of 127.0.0.1.

    4. Check Windows Firewall.

27. DEVELOPMENT RULES
=====================

1. Never invent current weather values when the station has no data.
   Use null and let the frontend show a loading/offline state.

2. Keep ML models loaded in memory.

3. Keep normal forecast results cached.

4. Use /forecast/range for custom date ranges.

5. Do not expose the development server directly to the public
   internet.

6. Humidity and wind direction should remain live measurements until
   enough historical data exists to train models for them.

7. The current CSV-based forecast is a development-stage system.
   The production system should use MongoDB and current station data.

8. Forecast values are predictions, not guarantees.

9. Keep this document as the backend API reference while building
   the AgroWeather frontend.
